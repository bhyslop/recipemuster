## Carried BUK rows — a curated subset, and a shrinking bridge

Both statements are load-bearing; either one alone misreads the list.

**A curated subset, never a mirror.** These are BUK-owned closed documents, kept
here only because recipemuster's own files still cite them — `Tools/buk/vov_veiled/`
left this consumer tree with the kit's veiled half. The list carries what this tree
cites and nothing else, so it is short by construction and is never authoritative
for BUK. BUK's whole veiled index lives at the kit's primary home; a reader who
needs it must read it there, and must not infer from a token's absence here that
BUK does not have one.

**A shrinking bridge, never a permanent surface.** As the veiled-acronym reference
lint drains closed-doc citations in delivered files down to rivets, these rows
follow the citation census down, and a row that reaches zero citations drops. The
three below are a floor measured at the fold, not a constant.

This list does double duty, and one duty misread as the other corrupts both. It is
the **resolution map** for the citations still standing — what a reader follows to
reach the document. It is also this tree's **per-kit roster** of tokens a delivered
file must not name, which the veiled-acronym reference lint reads. For the roster
duty these tokens are recipemuster's, whatever kit owns them upstream: with no buk
veiled index left in this tree, this file is the whole roster.
